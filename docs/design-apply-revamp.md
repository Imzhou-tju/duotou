# 添加投递界面改版方案

对应调研报告：`docs/audit-apply-module.md`

---

## 1. 设计目标

1. 一眼看出哪里可以打字 —— 所有可输入控件统一一套外观，聚焦态一致。
2. 一眼看出层级 —— 单位卡内部分「投递信息 / 备注 / 岗位」三段，各段有分隔与标题。
3. 高频项不走长滚动 —— 单模式下「当前阶段」紧跟表单主体，各阶段日期折叠可展开。
4. 单位下的多岗位在列表、详情、筛选三处都能看见。

---

## 2. 表单改版

### 2.1 输入框与视觉层级

**一套输入样式，三个层级。**

| 层级 | 场景 | 样式 |
| --- | --- | --- |
| 主输入 | 页面白卡上的字段（单位名称、集团名称、Base、链接…） | 白底 + `1px solid --border` + 10px 圆角 + 46px 高 |
| 卡内输入 | 单位卡体内的字段（具体单位、Base、投递日、备注、岗位名） | 同主输入（白底 + 1px 边框），因为单位卡底改为白色，卡体区加浅灰底衬托 |
| 聚焦态 | 全部 | 边框 `--brand` + `0 0 0 3px rgba(43,108,255,.12)` 光晕 |

**根因消除**：删掉 `.g-row input { border:none; background:transparent }` 与 `.pi-name { border:none }` 这两处去除边框的规则。单位卡底色由 `--bg` 改为 `#fff` + 1px 边框，卡体内部用 `--bg` 做浅底，输入框在其上是白底带边框 —— 与静态文字一眼区分。

**占位符去重**：

| 字段 | 旧 | 新 |
| --- | --- | --- |
| 岗位名 | label「岗位名称」+ placeholder「岗位名称，选填」 | label「岗位」+ placeholder「如 AI 应用开发岗」 |
| 单位卡内岗位 | 小标题「该单位下的岗位」+ placeholder「岗位名称，选填」 | 小标题「该单位下的岗位（2）」+ placeholder「如 软件开发岗」 |

### 2.2 单位卡结构

```
┌─ .u-card ──────────────────────────────────┐
│ .u-head   单位 1                    [×]    │  浅灰底 · 12px 灰字序号 + 右侧删除
├─ .u-body ──────────────────────────────────┤
│  .u-sec「投递信息」                         │  12px 灰字，段与段之间 1px 上边框
│   ┌ 具体单位 / 分行 ─────────────────────┐  │  白底输入框
│   ┌ Base 地 ──────┐  ┌ 投递日 ─────────┐  │  桌面两列 / 移动两列
│  .u-sec「备注」                             │
│   ┌ 备注（2 行）─────────────────────────┐  │
│  .u-sec「该单位下的岗位（2）」              │
│   ① [如 AI 应用开发岗        ] [×]         │  .p-row 白底输入框 + 序号徽标
│   ② [如 软件开发岗           ] [×]         │
│   ＋ 添加岗位                              │
└────────────────────────────────────────────┘
```

- 段落之间用 `border-top: 1px solid var(--border)` + `padding-top: 14px` 分隔，替代现在的一段糊在一起。
- 岗位行加序号徽标 `.pi-idx`（1/2/3，20px 圆形，`--brand-soft` 底），行与行之间 8px 间距，删除按钮 40×40 命中区。
- 卡片 padding 改为左右对称的 `12px`（原来 `4px 8px 8px 4px`）。

### 2.3 布局

**桌面端（≥720px）**

`.form-card` 仍用两列网格，但明确各字段的占格，消除空洞：

| 模式 | 第一行 | 第二行 | 第三行 | 第四行 | 第五行 |
| --- | --- | --- | --- | --- | --- |
| 单个单位 | 单位名称（跨两列） | 二级单位 \| 集团名称 | 岗位区（跨两列） | Base 地 \| 投递链接 | 备注（跨两列） |
| 集团投递 | 集团名称（跨两列） | 单位卡列表（跨两列） | 投递链接（跨两列） | | |

单位名称跨两列是刻意的：它是必填主键、又常是长文本，跨列后既消除空洞又强化主次。

**移动端（<720px）** 全部单列堆叠；单位卡内「Base 地 / 投递日」保持一行两列（投递日 `flex: 0 1 auto`，`min-width: 130px`）；岗位行 `input` `flex:1` + 删除按钮固定 40px。

**小屏加固（<360px）**：投递日输入框降到 `flex: 1 1 120px`；岗位行删除按钮 36px；卡 padding 收到 10px。不缩字号（`<600px` 已有 16px 防 iOS 缩放规则）。

### 2.4 流程调整

**单模式：阶段区上移。**

现在的顺序是「表单卡 → 当前阶段 → 各阶段日期 → 删除」，阶段区在表单外的第二屏。改为：

```
.form-card
├── 分段控件
├── 字段（单位名称 … 备注）
├── .u-sec「当前阶段」+ #edit-stages chips
└── #sec-dates  折叠区（默认收起）
     「各阶段日期（已填 3 项）」  ▸
```

- 「当前阶段」进表单卡，不再需要滚动找。
- 「各阶段日期」默认折叠，标题显示已填项数，点开展开日期行 —— 不用的人少滚动一屏，用的人点一下就到。
- 集团模式下不再整块隐藏，而是在表单卡底部显示一行说明卡：「集团投递的阶段在各条记录的详情里单独推进」，让用户知道阶段去哪了。

**模式切换**：切换后 `edit-scroll.scrollTop = 0`，并把分段控件下方的说明文案同步改写（单模式：「一个单位，可填多个岗位」；集团模式：「一个集团，含多个单位，每个单位可填多个岗位」）。已填数据不丢（沿用现有 `draftUnits` 保留逻辑）。

**保存按钮**：点击后 `disabled = true` + 文案「保存中…」，完成后恢复，避免慢网络重复提交。

### 2.5 校验与错误反馈

从「toast 孤岛」改为「行内错误 + toast 摘要」：

```js
markError($('#f-company'), '请填写单位名称');   // 输入框 .err + 下方 .field-err 红字
clearError($('#f-company'));                   // 输入时即时清除
```

| 规则 | 触发时机 | 反馈 |
| --- | --- | --- |
| 单位名称必填（单模式） | 点保存 | 输入框红边 + 行内「请填写单位名称」+ toast，并 `scrollIntoView` 到该字段 |
| 集团名称必填（集团模式） | 点保存 | 同上 |
| 集团模式至少一个单位或岗位 | 点保存 | 行内挂在单位卡列表下「至少填一个单位或岗位」 |
| 岗位重名 | 输入即校验 | 保留现有 toast + 输入回滚，**补**一个 1.5 秒的输入框红边闪动 |
| 单单位岗位 > 10 / 单位 > 20 / 单次 > 60 | 实时 | 按钮置灰 + 文案（现有逻辑保留） |
| 投递日为空 | 允许 | 无错误（可选字段） |

错误样式：`input.err { border-color: var(--danger); box-shadow: 0 0 0 3px rgba(235,87,87,.12); }`，`.field-err { color: var(--danger); font-size: 12px; margin-top: 6px; }`。

## 3. 多岗位的展示与查询

### 3.1 数据与兼容

**不改表结构。** 一条记录仍是一个「单位 × 岗位」。单位身份由派生键得到：

```js
function unitKey(r) { return (r.company || '') + '\u0000' + (r.sub_unit || ''); }
```

历史数据无需迁移：`company` 是 `not null`，`sub_unit` 为空时单位键就等于公司名，行为与今天一致。

### 3.2 列表聚合：集团 → 单位 两级

新增统一的 `bucketize(recs)`，产出有序桶数组：

1. 按 `group_name`（非空）分组，组内 ≥ 2 条 → **集团桶**。
2. 剩余记录按 `unitKey` 分组，组内 ≥ 2 条 → **单位桶**；仅 1 条 → **单卡**。
3. 桶内记录按 `update_time` 倒序；桶之间按「桶内最近活动时间」倒序。

| 卡片类型 | 主标题 | 副文 | 说明 |
| --- | --- | --- | --- |
| 集团桶 | 集团名 | `3 个单位 · 5 个岗位 · 最新进展 <阶段> <日期>` | 保留现有 `groupProgress` 算法 |
| 单位桶 | 二级单位（有）否则公司名 | `2 个岗位` + 岗位 chip（最多 3 个，多出显示 `+2`） | 新增 |
| 单卡 | 公司名 | 沿用现有 `recCardHTML`（流水线图） | 不变 |

> 单卡仍显示完整流水线；桶卡不显示流水线，改为「岗位 chip + 最新进展」，避免卡片过高（一个桶里可能有 10 条记录）。

### 3.3 详情

| 弹层 | 内容 | 入口 |
| --- | --- | --- |
| 集团弹层 | 顶部集团名 + `N 个单位 · M 个岗位`；内部**按单位二级分组**：单位名行 + 其下岗位行（岗位名 · Base · 阶段 pill · 最近日期） | 点集团桶卡 |
| 单位弹层（新增 `openUnitSheet`） | 顶部单位名；列出该单位下所有岗位，每行 `阶段 pill + 最近日期`；底部「＋ 在此单位下新增岗位」 | 点单位桶卡 |
| 单条详情 | 顶部公司名 + 阶段；新增「该单位其他岗位」区（同 `unitKey` 的其它记录，最多 5 条，点击直接切到那条） | 点单卡 / 从上级弹层点某条 |

单条详情里的「该单位其他岗位」解决调研里「看不出同一个单位还投了什么」的问题，且不必再回列表找。

### 3.4 筛选、排序、分页

搜索页扩为筛选面板：

| 控件 | 字段 | 匹配方式 |
| --- | --- | --- |
| 关键字 | `company / sub_unit / position / remark / base / group_name` | 现有：全字段子串（不区分大小写） |
| 单位 | `company + sub_unit` | 子串 |
| 岗位 | `position` | 子串 |
| 阶段 | `stage` | chips 精确（保留） |
| Base | `base`（含归一化值） | 子串（保留） |

- 「单位」「岗位」是独立输入框而非下拉：岗位名是自由文本，没有字典；下拉会列不全。
- 顶部实时显示双口径计数：`命中 12 条记录 · 涉及 4 个单位`。
- 提供「清空筛选」按钮（有任一条件时显示）。

**排序**（新增下拉，客户端排序）：

| 选项 | 规则 |
| --- | --- |
| 最近更新（默认） | `update_time desc` |
| 投递日期 | `apply_date desc`，空值排最后 |
| 阶段进度 | 按 `STAGES.indexOf(stage)` 降序，终态（拒绝/放弃）排最后 |

**分页**：

- `PAGE_SIZE = 20`，按**桶/卡片数**计（不是记录条数），保证翻页边界不劈开一个单位/集团。
- 底部「加载更多」按钮显示 `已显示 20 / 共 46 项`；全部加载后隐藏。
- 任一筛选或排序条件变化 → 重置到第 1 页并回到列表顶部。

### 3.5 改动范围与影响面

| 文件 | 改动 | 风险 |
| --- | --- | --- |
| `index.html` | 表单区重排（单位卡由 JS 生成，模板在 `renderUnits`）；字段容器占格类；阶段区移入表单卡 + 折叠块；搜索页加「单位 / 岗位 / 排序 / 清空」；列表底部加「加载更多」容器 | 低（纯结构） |
| `style.css` | 新增 `.u-card/.u-head/.u-body/.u-sec/.field-err/.pi-idx/.bucket-*`；删除旧的 `.g-row` 一组规则，`.p-row/.pi-name` 改为带边框 | 低 |
| `app.js` | 重写 `renderUnits/renderPositions`；调整 `renderEdit` 渲染顺序；新增 `unitKey / bucketize / renderBucketCard / openUnitSheet / 排序与分页状态`；扩展 `filteredRecords / renderSearch`；新增 `validateForm / markError / clearError`；`setModeUI` 补滚动复位与说明文案 | 中 |

**不改动的部分（接口契约保持）**：`saveRecord`、`saveGroupRecord`、`patchSheetDate`、`deleteRecord`、`normalizeLocation`、`exportCSV`、`loadRecords` 的读写语义与字段集。所有改动限定在「渲染 + 派生 + 校验」层，写入路径零改动 —— 即便聚合逻辑有问题，也只会影响显示，不会写坏数据。

**回退方式**：改动一次性提交，`git revert <commit>` 即回到当前状态；`docs/` 下的设计文档与代码解耦，可独立保留。

## 4. 落地顺序

1. 样式层：输入框统一（删掉去边框规则）+ 单位卡/岗位行重排。
2. 结构层：阶段区移入表单卡 + 折叠、桌面占格、模式切换说明文案。
3. 校验层：`markError/clearError` + 保存按钮 loading 态。
4. 展示层：`bucketize` + 单位桶卡 + 单位弹层 + 详情「该单位其他岗位」。
5. 查询层：单位/岗位筛选 + 排序 + 分页。
6. 验证：Playwright 覆盖单模式多岗位、集团多单位多岗位、编辑分流、聚合、筛选排序分页；移动 390 与桌面 1280 各截一版。
